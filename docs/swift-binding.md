# Swift UniFFI binding spike

Status: Rust bridge and generated sources implemented; **Apple build/runtime gate
pending**. No production switch, Xcode validation, startup/bridge benchmark result,
or device claim. Exact host contract: [`apps/ios/CORE_API.md`](../apps/ios/CORE_API.md).

## Toolchain and artifacts

- Rust 1.97.1 (workspace pin).
- UniFFI runtime/macros/generator **=0.32.2**, locked together. The crate-local
  `uniffi.toml` selects Swift module `SudokuCoreBindings` and C module `SudokuCoreFFI`.
- Selected Apple gate: Xcode **16.4**, Swift **6** language mode, complete strict
  concurrency, iOS **17.0** minimum. This selection is unverified here; changing
  Xcode requires rerunning/recording the gate, not silently declaring compatibility.
- Architectures: `aarch64-apple-ios` + `aarch64-apple-ios-sim`; optional
  `x86_64-apple-ios` simulator only with `INCLUDE_X86_64_SIM=1`.
- Generated, checked-in files under `apps/ios/Sources/SudokuCoreBindings/`:
  `SudokuCoreBindings.swift`, `SudokuCoreFFI.h`, `SudokuCoreFFI.modulemap`.
- Build products/package/checksum manifest: `target/ios-core/` (untracked).
  The generator CLI feature is separate; iOS static libraries exclude CLI deps.

## Reproduce

Linux or macOS source generation (no standalone/global bindgen installation):

```sh
bash scripts/build-ios-core.sh --generate-only
git diff -- apps/ios/Sources/SudokuCoreBindings
cargo +1.97.1 test -p sudoku-ffi --locked
cargo +1.97.1 clippy -p sudoku-ffi --all-targets --all-features --locked -- -D warnings
cargo +1.97.1 fmt -p sudoku-ffi -- --check
cargo +1.97.1 doc -p sudoku-ffi --no-deps --locked
```

Generation disables optional swift-format so host formatter versions do not change
artifacts. The script discovers crate-local UniFFI configuration through Cargo
metadata, builds a release host library, and extracts matching ABI metadata.

macOS packaging:

```sh
DEVELOPER_DIR=/Applications/Xcode_16.4.app/Contents/Developer bash scripts/build-ios-core.sh
```

The script installs Rust targets, builds release static libraries, copies generated
C headers/module map, and runs `xcodebuild -create-xcframework`. Device and simulator
remain distinct slices; optional simulator architectures alone are combined by
`lipo`. It assembles a tiny Swift package from
`crates/sudoku-ffi/swift-tests/Package.swift`, generated Swift, binary XCFramework,
and shared fixtures. Link the package product `SudokuCoreBindings`; do not add the
C header alongside Swift as a mixed-language target. Matching Rust binary and
generated code must ship as one versioned artifact.

Run from `target/ios-core` on macOS (choose an installed simulator identifier):

```sh
xcodebuild -list
xcodebuild -scheme SudokuCoreSpike-Package -destination 'platform=iOS Simulator,id=SIMULATOR_UUID' \
  -configuration Debug SWIFT_VERSION=6 SWIFT_STRICT_CONCURRENCY=complete CODE_SIGNING_ALLOWED=NO test
xcodebuild -scheme SudokuCoreSpike-Package -destination 'generic/platform=iOS' \
  -configuration Release SWIFT_VERSION=6 SWIFT_STRICT_CONCURRENCY=complete CODE_SIGNING_ALLOWED=NO build
```

Confirm the actual generated package scheme with `-list`; these macOS commands
cannot be exercised here. Retain `build-manifest.txt`, test result bundles, and
tool versions with release artifacts. Also run simulator Release tests and ARC
allocation/leak instrumentation over the repeated-session test. Device startup,
bridge/storage timings and signed app archive validation are separate gates.

## Concurrency and ABI findings

Generated byte vectors are Foundation `Data`; notes `[Data]`. Constructors are
`GameSession(puzzle:id:at:)`, static `restore(puzzle:record:)` and
`importJson(puzzle:json:)`; errors preserve uppercase cases (e.g. `.StaleCandidate`).
Full names/record layouts are documented in the host contract.

There are no callbacks or async functions across the ABI. Wrapper destruction
releases UniFFI handles to Rust `Arc`s. Session/token state uses mutexes; lock poison
becomes typed `Unavailable`. Candidate acceptance takes its `Option` exactly once,
then delegates identity/generation checks to core. Failed acceptance also consumes
the token. Projection values remain readable after consumption; DTO edits cannot
forge or alter a token. Host durability is a documented precondition, not something
the core can verify.

UniFFI 0.32.2 emits conditional `Sendable` for records/enums under compiler 6 and
generator-owned `@unchecked Sendable` reference wrappers/handle map. These were
inspected, not hand-added or patched. Reference wrappers remain repository-local;
value projections cross to presentation. Strict Swift 6 compilation is still the
gate for those generated conformances. Do not suppress failures with extra
unchecked conformances or edit generated sources.
