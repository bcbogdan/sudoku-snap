# UI design review

Read-only review, 2026-11-05. Lens: `emil-design-eng`; reference: `design.md`, all ten pages of `design_language.pdf`, design implementation plan/progress/handoff. No UI implementation or baseline updates.

## Verdict

The board, bundled typography, restrained surfaces, theme contrast, and explicit toggle states form a coherent foundation. Finish composition and repeated interactions rather than add decorative motion. Mobile collection/detail screens currently spend too much space on supporting information; replay does not give its current move sole visual priority.

## Keep / motion guidance

- Keep instant board selection, arrow navigation, keypad state, notes, and replay stepping. These repeat hundreds of times; no stagger, pop, shake, or animated highlight travel needed.
- Existing press-color feedback is sufficient. Do **not** add scale animations to every cell/key merely to make the UI feel responsive. Hover effects are already gated behind hover/fine-pointer media queries (`Button.css:60–64`, `NumberKeypad.css:60–64`, `PuzzleCard.css:89–98`).
- Completion alone receives a short 220ms transform/opacity animation, with a 100ms opacity-only reduced-motion branch (`AttemptHistory.tsx:44–60`). This is appropriately rare. Consider suppressing its movement for keyboard-origin completion; do not animate keyboard input itself. No completion sweep or haptics recommended.
- Copy feedback already uses short, property-specific transitions and reduced-motion handling (`app/components/CopyNotice.css:24–46`). Keep it interruptible.
- Preserve the square bounded board, non-color mistake/uncertainty rings, visible focus, explicit On/Off toggles, and readable light/dark typography. The smaller mobile board cells are an acknowledged geometric constraint, not a reason to shrink the keypad.
