## Actual generated API

All domain calls are synchronous. Methods marked `throws` below throw `CoreError`.
UniFFI maps `Vec<u8>` to Foundation **`Data`**, not `[UInt8]`; use
`Data(digits)` for exactly 81 bytes of values 0–9, not ASCII or UTF-8 digits.
Notes are `[Data]`: exactly 81 sorted, distinct sets of digits 1–9.

flat camelCase layout. `nil` optional timer/share/undo values correspond to absent
JSON properties; completion/duration are required nullable JSON properties.
Generated records are not `Codable`: map storage columns/host DTOs explicitly.
Ready restoration and session restoration validate all metadata/history; incoming
records are untrusted until those constructors succeed.

## Required repository transaction order

Keep ready/session/candidate references inside one repository actor or serial
executor. Synchronize all scenes through that repository. Rust mutexes protect
individual calls, **not** a host database transaction.

1. Read/check latest durable records inside the transaction; match or restore the
   resident session. Storage generations must cover timer and puzzle changes too.
2. Prepare with the host clock/focus interval. Read `candidate.projection()`.
3. Atomically write `projection.header` and optional `appendedMove`. An unchanged
   candidate still must follow the serialized acceptance order.
4. Commit, then `try session.accept(candidate: candidate)`; publish
   `projection.current` only after successful acceptance. Acknowledge the focus
   interval only after commit. Do not suspend inside read/check/write/commit.
5. Failed/cancelled persistence: discard the candidate, retain pending focus
   coverage, leave UI/session unchanged. Commit succeeded but accept failed:
   reload durable state; never replay the command.

Acceptance consumes the core token even when it fails stale/foreign validation;
second acceptance fails. Every successful acceptance advances generation,
including unchanged checkpoints, invalidating siblings. Generation is local to
this session, not a database CAS token. A retained candidate can still return its
immutable projection after accept/discard, but cannot be accepted again.

Creation/finalization: derive ready puzzle and new session, then atomically persist
`ready.record()` plus `session.exportRecord()` before publishing either. Review
draft records similarly before publishing the returned draft. `exportRecord` is
O(history), intended for creation/backup/explicit reload, never each keypress.
Preparation/projection copy only fixed 81-cell positions, header, and at most one
move, independent of history length (apart from identity string lengths).

## Boundary and error policy

Core validates cell 0–80, digits 0–9, note sets, times/counters at most
9,007,199,254,740,991, intervals, canonical metadata, history, and completion locks.
Use Swift exact numeric conversions for user/storage inputs before calling; never
clamp or truncate. Name normalization is JS whitespace and **80 UTF-16 units**,
not `String.count`; use `normalizeName`. Share import returns both historical
identity keys; check both atomically. Names/URLs/IDs/clocks/photos remain host-owned.

Actual error cases are capitalized:
`InvalidBoard`, `InvalidMove`, `InvalidNotes`, `InvalidHistory`,
`InvalidRecord(reason: String)`, `InvalidTime`, `InvalidInterval`, `Overflow`,
`Locked`, `StaleCandidate`, `TooFewClues`, `NoEmptyCells`, `NoSolution`, `Ambiguous`,
`InvalidLink`, `ConflictingClues`, `InvalidName`, `Unavailable`.
Localize from cases, not generated `errorDescription` (a reflection string).
`Unavailable` means a poisoned mutex: invalidate/reload. Storage errors are host
errors. JSON decode failures expose a fixed reason, never an entire record.

## Ownership/concurrency

No callbacks, delegates, async Rust functions, or Swift closures cross the ABI.
Generated Swift reference wrappers own UniFFI handles to Rust `Arc`s; lowering
clones a handle, generated `deinit` frees it. Dropping the last unaccepted
candidate aborts; `discard()` explicitly drops its core token sooner. Dropping a
session does not invalidate detached projection data. Do not use generated
`unsafeFromHandle`, `NoHandle`, converter helpers, or subclass reference wrappers.

UniFFI itself generates `@unchecked Sendable` on its reference wrappers and locked
handle map. No hand-written conformance or generated-code patch was added. Rust
mutable state is mutex-protected, puzzles/projections immutable; nevertheless keep
reference objects repository-isolated. Transfer value projections or map to
host-owned presentation values. Swift 6 compilation/lifetime checks remain pending
on macOS; Linux generation is not evidence of a passed Swift gate.
